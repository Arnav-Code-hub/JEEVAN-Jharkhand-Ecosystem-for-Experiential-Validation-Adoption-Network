Phase 1 Citizen Intake

JEEVAN Citizen Intake

A clean, accessible intake system for rural Jharkhand communities designed for low-bandwidth environments with voice-first interaction.

🌿

Design Principles

What shapes this system's visual identity

乡村
Rural-First

Designed for intermittent connectivity, low-bandwidth conditions, and diverse literacy levels across Jharkhand's rural communities.

🗣️
Voice-First

Voice recording and playback is the primary interaction mode, with text as fallback for those who prefer it.

🌍
Multilingual

Native language support (Hindi, English, regional dialects) with automatic translation where needed.

✅
Verifiable

Every citizen submission generates an immutable record with geotagging and timestamp for transparency.

System Architecture

How components communicate during citizen intake

📱 Citizen App
↓
☁️ API Gateway
↓
📝 Intake Service
📦 PostgreSQL
⇄
🕸️ Neo4j

Citizen submissions flow from mobile app to NestJS API, validated and stored in PostgreSQL with Neo4j for competency relationships. The ML service processes submissions asynchronously for pattern analysis.

Implementation Timeline

Phase 1 sprint schedule

Week 1-2
Database Schema & Citizen Entity
Define Supabase tables for citizen intake, including geotagging, voice recording references, and status tracking.
Week 2-3
Intake API Endpoints
Create POST /citizens for intake, GET /citizens/:id for status tracking, with WhatsApp voice-bot webhook integration.
Week 3-4
Offline Sync Logic
Implement local-first data storage in Flutter app with automatic sync when connectivity is restored.
Week 4-5
Admin Review Queue
Build G1 gate dashboard for government officials to review and verify citizen submissions.
